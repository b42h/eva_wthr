# Нічний режим для CLOUDY / RAIN / FOG / SNOW — дизайн

> Дата: 2026-05-29
> Файл, що змінюється: `main/eva_weather_canvas.c`
> Тип: візуальний рендер (фон неба), без зміни даних/API.

## Проблема

Запит: «Хмарно, RAIN, FOG, SNOW також мають мати нічний режим».

**Обсяг охоплює всю «нейтральну» сім'ю типів**, не лише ці чотири:
RAIN, HEAVY_RAIN, THUNDERSTORM, SNOW, SLEET, HAIL, FOG, CLOUDY. Вони всі
ділять одну й ту саму ваду фону (фіксований денний градієнт) і одну
гілку `is_night_kind`, тож лишити, скажімо, THUNDERSTORM зі світлим
денним небом опівночі було б очевидною неконсистентністю поряд із
нічним RAIN. CLEAR / PARTLY_CLOUDY не входять — вони вже мають повний
day↔night цикл.

Розслідування показало, що це **майже повністю вже працює**, крім фону неба:

`is_night_kind()` (`eva_weather_canvas.c:1714`) для «нейтральних» типів
(RAIN, HEAVY_RAIN, THUNDERSTORM, SNOW, SLEET, HAIL, FOG, CLOUDY) уже
повертає `true` після заходу / до сходу сонця за настінним годинником.
Завдяки цьому **вже** адаптуються вночі:

- місяць замість сонця (`eva_weather_canvas.c:1921`)
- нічний tint хмарних страйпів (`update_cloud_tints`, :2330)
- темніший base_col хмарних спрайтів (:2256)
- зменшений (0.6×) годинник (:892)
- вимкнені sun-glare (:1193) і day-sky-depth (:1161)

**Єдина справжня діра:** `sky_for_kind()` (`eva_weather_canvas.c:1105`)
повертає **фіксований денний градієнт** для цих типів незалежно від часу.
О 2:00 overcast усе одно світло-сірий `{150,160,170}`. Це фон на весь
екран — тому вся сцена «не виглядає нічною», хоча передній план (місяць,
хмари, годинник) уже нічний.

## Поточні (денні) палітри в `sky_for_kind`

| Kind | top | bottom |
|---|---|---|
| RAIN / SLEET | `{34,44,60}` | `{82,92,104}` |
| HEAVY_RAIN | `{18,26,40}` | `{52,60,74}` |
| THUNDERSTORM | `{12,18,30}` | `{46,48,58}` |
| SNOW / HAIL | `{116,132,150}` | `{205,214,220}` |
| FOG | `{130,138,145}` | `{215,216,210}` |
| CLOUDY | `{78,92,108}` | `{150,160,170}` |

(CLEAR / PARTLY_CLOUDY уже проходять через `clear_sky_palette` — повний
day↔twilight↔night цикл. Їх логіку **не міняємо по суті**, лише
рефакторимо спільну частину.)

## Рішення (обраний підхід)

**Винести «night-ness» криву + плавно інтерполювати кожен тип день→ніч.**

### Чому саме так (відхилені альтернативи)

- **A — окремі if-гілки day/night на кожен тип.** Дублює timing-логіку,
  дає різкий стрибок кольору на sunrise/sunset. Відхилено (користувач
  обрав плавний twilight-перехід).
- **B — пустити всі типи через `clear_sky_palette`.** Притягне теплий
  оранжевий glow на горизонт. Відхилено: реальне похмуре/дощове небо
  ввечері НЕ світиться закатом — хмари його закривають.
- **Обраний — спільна night-ness крива + per-kind лерп.** Переюзає
  існуючий twilight-таймінг (`civil_twilight_minutes()` +
  `sun_curve()`), плавно, БЕЗ orange glow. Кожен тип лишає свій денний
  характер і одержує власну темну (вугільно-сіру) нічну версію.

### Естетика (рішення користувача)

- Сірий→вугільний, **без оранжевого glow**.
- Рівень темряви: **помірно темний** (вугільно-сірий, не чорний) — щоб
  хмари/краплі ще читалися на фоні.
- FOG лишається світлішим за решту вночі (туман розсіює світло
  міста/місяця — не стає вугільним).

## Компоненти

### 1. Нова чиста функція `sky_nightness(int m, int sr, int ss) → float`

Повертає 0.0 (повний день) … 1.0 (глибока ніч). Витягується з логіки,
що **вже існує** всередині `clear_sky_palette` (`eva_weather_canvas.c:1041`):

- день (сонце над горизонтом) → `0.0`
- присмерок (`past` у межах `DUSK = civil_twilight_minutes()`) →
  `past / DUSK` (0 на термінаторі … 1 глибока ніч)
- ніч → `1.0`

```c
/* 0 = повний день, 1 = глибока ніч. Та сама крива, що керує
 * нічним фактором у clear_sky_palette — винесена для переюзу
 * нейтральними типами (RAIN/CLOUDY/FOG/SNOW...). */
static float sky_nightness(int m, int sr, int ss)
{
    const float DUSK = civil_twilight_minutes();
    /* … та сама логіка визначення day/twilight/night, що зараз
       інлайнена в clear_sky_palette, повертає 0..1 … */
}
```

### 2. Рефактор `clear_sky_palette`

Замінити інлайновий розрахунок нічного фактора на виклик
`sky_nightness()`. **Поведінка CLEAR/PARTLY не повинна змінитися** —
перевіряється скріншотом (регрес-тест нижче). Денні keyframes (twi/day,
orange горизонт) лишаються тільки в цій функції.

### 3. Нові нічні палітри (вугільно-сірі) + лерп у `sky_for_kind`

Для кожного нейтрального типу:

```c
sky_t day   = { "<kind>", <поточні денні кольори> };
sky_t night = { "<kind>-night", <нові нічні кольори> };
float n = sky_nightness(m, sr, ss);
return (sky_t){ day.name,
                lerp_rgb(day.top, night.top, n),
                lerp_rgb(day.bot, night.bot, n) };
```

Нічні палітри (помірно темні, нейтрально-сірі):

| Kind | night top | night bottom |
|---|---|---|
| CLOUDY | `{22,26,34}` | `{42,48,58}` |
| RAIN / SLEET | `{18,22,30}` | `{40,46,56}` |
| HEAVY_RAIN | `{12,16,24}` | `{30,36,46}` |
| THUNDERSTORM | `{10,14,22}` | `{28,32,42}` |
| SNOW / HAIL | `{30,36,46}` | `{58,66,80}` (трохи світліше — сніг відбиває) |
| FOG | `{40,44,52}` | `{70,74,82}` (найсвітліший — туман розсіює) |

(Точні значення — стартові; фінальні підкрутяться за скріншотом на
залізі. Денні значення в таблиці лишаються незмінними.)

### Дані / потік

Без змін. `sky_for_kind` так само викликається раз на rebake фону.
Додається виклик `sky_nightness` (десяток float-операцій) + два
`lerp_rgb`. На FPS не впливає (фон і так перемальовується раз на rebake,
не щокадру).

## Перевірка частинок / туману

Після зміни фону — переконатися, що краплі (P_RAIN), сніжинки (P_SNOW),
туман (P_FOG) читаються на темному нічному небі. Краплі/сніг уже світло-
сірі, тож імовірно ОК. Якщо контраст замалий — підкрутити колір/alpha у
відповідній гілці малювання частинок. **Не міняємо** систему частинок,
лише, за потреби, кольорові константи.

## Граничні випадки

- **Forced day debug-kinds.** CLOUDY/RAIN/... не мають forced day/night
  варіантів (на відміну від CLEAR_DAY/CLEAR_NIGHT). `weatherdebug cloudy`
  опівдні дасть денний фон, опівночі — нічний, бо `sky_nightness` іде за
  настінним годинником. Це консистентно з рештою ефектів (місяць/хмари
  для тих самих типів уже так поводяться через `is_night_kind`). ОК.
- **Незасинхрений / debug годинник** (sunrise/sunset = -1).
  `sun_events()` уже має внутрішній фолбек на типове вікно; `sky_nightness`
  просто читатиме його. Без окремої обробки.
- **Зсув години в test-режимі** (`eva_clock` hour-offset). `minutes_now()`
  уже враховує offset, тож night-ness слідуватиме за тестовим часом —
  саме те, що треба для перевірки.

## Інваріанти, яких НЕ торкаємось (з CLAUDE.md)

- `DPI_BUFFER_NUMS = 1`, без `AVOID_TEAR`+`DIRECT_MODE`.
- `sw_rotate=true`, `LV_DISPLAY_ROTATION_270`.
- `°` гліф: `eva_font_uk_22` його не має — банер не чіпаємо.
- Не міняємо систему частинок/хмар структурно, лише кольори за потреби.

## Тестування (залізо + CDC screenshot)

ESP-IDF v5.5.4. Білд + флеш як у README. Через CDC:
`weatherdebug <kind>` + `screenshot`.

Послідовність:

1. **Регрес (день):** cloudy / rain / fog / snow вдень — мають
   виглядати як зараз (денні кольори незмінні).
2. **Регрес CLEAR:** clear-day, clear-night, partly-cloudy day/night —
   переконатися, що рефактор `clear_sky_palette` нічого не зламав.
3. **Нове (ніч):** ті самі cloudy/rain/fog/snow вночі (через зсув
   годинника або реальний нічний час) — небо вугільно-сіре, плавний
   перехід на присмерку, краплі/сніг/туман читаються.
4. **Присмерок:** перевірити плавність (немає різкого стрибка на
   sunrise/sunset).

## Очікуваний результат

Усі weather-типи мають консистентний день↔ніч цикл: фон неба темнішає на
присмерку синхронно з уже-нічними хмарами/місяцем/годинником. Похмурі/
дощові/сніжні ночі виглядають вугільно-сірими (фізично правильно, без
фальшивого заходу), туман — світліше-сірим.

## Фінальні нотатки реалізації (відвантажено 2026-05-29)

**Статус: зроблено, перевірено на залізі (CDC screenshot).**

Реалізовано як у плані:

- `sky_nightness(m, sr, ss)` додано в `eva_weather_canvas.c`;
  `clear_sky_palette()` зарефакторено на неї (поведінка CLEAR незмінна —
  підтверджено скріншотами clear-day/night, partly day/night).
- `sky_for_kind()` лерпить день→ніч для CLOUDY/RAIN/HEAVY_RAIN/
  THUNDERSTORM/SNOW/SLEET/HAIL/FOG. Денні кольори ідентичні старим
  (n=0), нічні — вугільно-сірі. Перевірено вдень (offset +9h) і вночі
  (offset 0 / реальний час 23:xx).
- Частинки (дощ/сніг/туман) читаються на темному небі — додаткового
  тюнінгу кольору не знадобилось.

**Розширення обсягу за запитом користувача — видалення `draw_fog_bands()`:**

Під час перевірки виявилось, що на «Хмарно наживо» (де clearoutside
віддає fog=96 % попри kind=CLOUDY) поверх сцени раз на bg-rebake
малювались **4 напівпрозорі синусоїди** (`draw_fog_bands`, гейт
`s_fog_pct >= 30`). Користувач відхилив цей ефект повністю («цих 4
синусоїд бути не повинно взагалі»).

- Спершу гейт звузили до `s_kind == WEATHER_FOG` — недостатньо
  (користувач хотів прибрати всюди).
- **Фінал: `draw_fog_bands()` видалено цілком** — і функцію, і єдиний
  виклик у render-loop bg-rebake блоці. Туман тепер передається лише
  палітрою неба + хмарними страйпами. Перевірено: forced `fog` і
  `cloudy` вночі — синусоїд нема на жодному.

**Не входило в цей реліз (окремий, давніший артефакт):** темні хвилясті
бенди на чистому нічному небі (cloud strips + RGB565 banding на темному
градієнті, задокументовано як очікуване в `TESTING_CLOUD_SPRITES.md`).
Не плутати з видаленими fog-синусоїдами.
